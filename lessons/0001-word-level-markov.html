Word-Level Markov Models

Lesson 1 · Build a text generator that creates 10K stories in under a second

Why This Matters

Your Ollama-based pipeline generates ~45 stories per minute. A word-level Markov model can generate 10,000 stories in under a second — a 600,000× speedup. The trade-off? Markov models are "dumber": they can't reason, they don't understand meaning, they just replay patterns they've seen. But for augmenting SLM training data, that's often enough.

More importantly: Markov models are the conceptual ancestor of every modern language model. GPT-4 is, at its core, a very fancy n-gram model with neural-network-shaped parameters. Understanding Markov chains gives you intuition for what all language models do: predict the next token given the previous context.

The Core Idea

A Markov model assumes the Markov property: the next word depends only on the previous n-1 words, not the entire history. This is obviously false for real language (a pronoun might refer to a noun 20 sentences back), but it works surprisingly well for short text.

Concrete Example

Consider this TinyStories sentence:

The little girl went to the park. She played on the swings.

A trigram model (n=3) breaks this into overlapping triples:

Context → Next word (The, little) → girl (little, girl) → went (girl, went) → to (went, to) → the (to, the) → park (the, park) → . (park, .) → She (., She) → played (She, played) → on (played, on) → the (on, the) → swings (the, swings) → .
Frequency table (the, little) → {girl: 1} (went, to) → {the: 1} (the, park) → {.: 1} (park, .) → {She: 1} (She, played) → {on: 1} (the, swings) → {.: 1}

When we generate, we sample from the frequency table: given a context, pick a next word proportional to how often it appeared in training. If a context appears multiple times with different continuations, the model captures the distribution of possibilities.

The Implementation

Here's the complete implementation. Pay attention to how simple it is — about 25 lines of core logic:

from collections import defaultdict, Counter
import random

class WordMarkov:
    def __init__(self, n=3):
        self.n = n
        self.model = defaultdict(Counter)

    def train(self, corpus):
        for tokens in corpus:                         # each story = list of words
            ctx = tuple(['<BOS>'] * (self.n - 1))  # pad start with BOS tokens
            for word in tokens + ['<EOS>']:           # append EOS at end
                self.model[ctx][word] += 1             # count: ctx → word
                ctx = ctx[1:] + (word,)               # slide window

    def generate(self, max_len=50):
        ctx = tuple(['<BOS>'] * (self.n - 1))
        out = []
        for _ in range(max_len):
            word = self._sample(ctx)
            if word is None or word == '<EOS>':
                break
            out.append(word)
            ctx = ctx[1:] + (word,)
        return ' '.join(out)

    def _sample(self, ctx):
        counts = self.model.get(ctx)
        if not counts:
            return None
        words, weights = zip(*counts.items())
        return random.choices(words, weights=weights, k=1)[0]

Three methods. That's it.

Key Insight: Why N=3?

The order n controls the fluency-diversity trade-off:

n Output example Problem
2 (bigram) "the went to played the little" No grammar — words don't agree
3 (trigram) "the little girl went to the park" Good balance
4 (4-gram) "the little girl went to the park and played on the swings" Starts copying training data verbatim

For TinyStories, n=3 is the sweet spot. Low enough to be creative, high enough to be grammatical.

from collections import defaultdict, Counter

class WordMarkov:
    def __init__(self, n=3):
        self.n = n
        self.model = defaultdict(Counter)

    def train(self, corpus):
        for tokens in corpus:
            ctx = tuple(['<BOS>'] * (self.n - 1))
            for word in tokens + ['<EOS>']:
                self.model[ctx][word] += 1
                ctx = ctx[1:] + (word,)

    def generate(self, max_len=40):
        ctx = tuple(['<BOS>'] * (self.n - 1))
        out = []
        for _ in range(max_len):
            counts = self.model.get(ctx)
            if not counts: break
            words, weights = zip(*counts.items())
            word = random.choices(words, weights=weights, k=1)[0]
            if word == '<EOS>': break
            out.append(word)
            ctx = ctx[1:] + (word,)
        return ' '.join(out)

Check your understanding

1. What happens if we set n=1 (unigram)?

Correct! A unigram model has no context — each word is sampled from the global frequency distribution.

2. Why can't a trigram model handle "The cat... it" coreference?

Correct! A trigram sees only 2 previous words, so it can't link a pronoun to a noun 5 words back.
