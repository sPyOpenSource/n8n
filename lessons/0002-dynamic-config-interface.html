Lesson 0002: The Dynamic Config Interface

Moving from a static server to one that can be managed in real-time.

1. The Static Limitation

In the first version of our server, settings like RATE_LIMIT_RPM were constants in server/config.py. To change them, you had to edit the file and restart the server. This is "Static Configuration".

For a tool meant to be a "bridge", this is a bottleneck. If you realize your provider is rate-limiting you, you want to change the limit now, not after a redeploy.

2. The Merge Hierarchy

To solve this, we implement a Configuration Hierarchy. Instead of one source, we use three, merged in a specific order of priority:

1. Environment Variables (Highest Priority)
Used for secrets (API Keys) and infrastructure-level overrides.
2. config.json (Medium Priority)
User-defined settings managed via the Admin UI. Persistent across restarts.
3. Hardcoded Defaults (Lowest Priority)
Sane fallbacks defined in the code.

This ensures that a developer can set a global default, but a user can override it in the UI, and a DevOps engineer can override both using an environment variable in a Docker container.

3. The ConfigManager Singleton

To prevent "split-brain" (where different parts of the app see different settings), we use a ConfigManager. This is a single object that handles the merge logic and provides the final value to the rest of the app.

# Conceptual Logic
def get_setting(key):
  if os.environ.get(key): return os.environ[key]
  if config_json.get(key): return config_json[key]
  return DEFAULTS[key]

4. The Admin Bridge

The Manager Interface is simply a UI that talks to this ConfigManager. When you click "Save" in the UI:

  1. The browser sends a JSON payload to POST /admin/config
  2. The server validates the settings
  3. The server writes the updated values to config.json
  4. The Router is signaled to reload its provider pool based on the new config

💡 Key Insight: State vs. Configuration

Configuration is what the system should do (Priority: Copilot > OpenAI). State is what the system is currently doing (e.g., "Current Active Provider: Copilot"). The Admin UI manages the configuration, and the Router translates that configuration into active state.
