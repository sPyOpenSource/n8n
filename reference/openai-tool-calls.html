Tool Calling — Wire Format

The exact JSON shapes opencode sends and expects.

Request: tools array

Sent alongside messages on every chat completion request.

{
  "model": "...",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."}
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "read_file",
        "description": "Read the contents of a file",
        "parameters": {
          "type": "object",
          "properties": {
            "path": {
              "type": "string",
              "description": "The file path"
            }
          },
          "required": ["path"]
        }
      }
    }
  ],
  "tool_choice": "auto"          // "auto" | "none" | "required" | {"type":"function","function":{"name":"..."}}
}
Key Detail: opencode always sends a tools array. If your server ignores it, opencode's agentic loop breaks immediately.

Response: tool_calls

When the model decides to call a tool, the response contains tool_calls instead of content.

Non-streaming

{
  "id": "chatcmpl-xxx",
  "object": "chat.completion",
  "choices": [{
    "index": 0,
    "message": {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_abc123",
          "type": "function",
          "function": {
            "name": "read_file",
            "arguments": "{\"path\":\"/tmp/test.txt\"}"
          }
        }
      ]
    },
    "finish_reason": "tool_calls"
  }]
}

Streaming (per-chunk delta)

Each streaming chunk carries a partial tool_calls delta:

data: {
  "choices": [{
    "index": 0,
    "delta": {
      "role": "assistant",
      "content": null,
      "tool_calls": [{
        "index": 0,
        "id": "call_abc123",
        "type": "function",
        "function": {"name": "read_file", "arguments": ""}
      }]
    }
  }]
}
data: {
  "choices": [{
    "index": 0,
    "delta": {
      "tool_calls": [{
        "index": 0,
        "function": {"arguments": "{\""}
      }]
    }
  }]
}
data: {
  "choices": [{
    "index": 0,
    "delta": {
      "tool_calls": [{
        "index": 0,
        "function": {"arguments": "path\":\""}
      }]
    }
  }]
}
data: {
  "choices": [{
    "index": 0,
    "delta": {
      "tool_calls": [{
        "index": 0,
        "function": {"arguments": "/tmp/test.txt\"}"}
      }]
    }
  }]
}
data: {
  "choices": [{
    "index": 0,
    "delta": {},
    "finish_reason": "tool_calls"
  }]
}
data: [DONE]

Conversation Loop: tool messages

After the assistant returns tool_calls, the client (opencode) executes them and appends tool role messages with the results:

{
  "role": "tool",
  "tool_call_id": "call_abc123",
  "content": "The file /tmp/test.txt contains: hello world"
}

These messages must be preserved across the conversation so the model sees what tools returned.

Streaming: finish_reason Values

The last chunk (delta: {}) before [DONE] must carry the correct finish reason:

ValueMeaning
"stop"Model finished normally (content is complete)
"tool_calls"Model decided to call one or more tools
"length"Response was cut off by max_tokens
"error"An error occurred mid-generation

Usage Metadata (Streaming)

The Vercel AI SDK expects a final chunk with usage before [DONE]:

data: {
  "choices": [],
  "usage": {
    "prompt_tokens": 105,
    "completion_tokens": 42,
    "total_tokens": 147
  }
}

This is not strictly required by the OpenAI spec (streaming usage is model-dependent), but the Vercel AI SDK uses it to report token consumption correctly.
