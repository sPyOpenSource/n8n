Token Reduction — Sliding Window

Keep system prompts, drop old conversation history.

The Pattern

LLM context windows fill up fast — especially with agentic loops (opencode tool calls, long system prompts). The fix: a sliding window over messages.

Algorithm
Extract all system role messages → always preserve
From the remaining non_system messages, keep only the last N
Rejoin: system + trimmed_non_system

Implementation

def trim_messages(messages: list[dict], max_messages: int = 15) -> list[dict]:
    if max_messages is None or not messages:
        return messages

    system = [m for m in messages if m.get("role") == "system"]
    non_system = [m for m in messages if m.get("role") != "system"]

    if len(non_system) <= max_messages:
        return messages

    trimmed = non_system[-max_messages:] if max_messages > 0 else []
    return system + trimmed

Config

# server/config.py DEFAULTS
"MAX_MESSAGES": 15,   # set to 0 to drop all conversation history
                       # set to null/None to disable trimming

Where It Runs

In server/api.py, right after messages are parsed and before they reach the router:

messages = [m.model_dump(exclude_none=True) for m in req.messages]
max_msgs = config.get("MAX_MESSAGES", 15)
messages = trim_messages(messages, max_messages=max_msgs)

Token Savings

ScenarioMessages BeforeAfterTokens Saved (est.)
Short chat (2 turns)66 (no trim)0
Medium agent session3016 (1 sys + 15 msg)~3,500
Long opencode session10016~12,500
With tool calls (no sys)5015~5,000
Caveat: Aggressive trimming loses context. The model won't remember earlier goals or decisions. Set MAX_MESSAGES per use case — opencode works well with 15–30, but chat UIs may need more.

Edge Cases

  • No system prompt → last N messages only
  • max_messages=0 → system prompts only, drops all conversation
  • max_messages=None → no trimming (passthrough)
  • Empty messages → returns empty list
